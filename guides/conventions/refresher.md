## Off the bundled competition the refresher discovers, then polls only when a match can be in play

The bundled schedule gates live polling for the World Cup; nothing did for any other competition, so the refresher polled around the clock.

## The bullet whole: "A refresher decides under the lock, and a throttle always has somewhere to be written"

The `AGENTS.md` "Conventions" bullet in full: its text as it stood on `main` before this section was added, with the clauses the code disproved corrected in place (`AGENTS.md` carries the same corrections wherever it keeps the clause). `AGENTS.md` now keeps its lead and a selection of its sentences and clauses, with a few joining words and a closing sentence of its own. A rule stated only here still holds: a sentence `AGENTS.md` leaves out is not a rule withdrawn. A reference in this text to "above" or to another bullet is to `AGENTS.md`: the bullets before this one there, and for one of the four bullets held whole, its own guide.

**A refresher decides under the lock, and a throttle always has somewhere to be written.** `runRefresh` takes a first look at the cache without the lock, and that look may only decide NOT to ask; a decision to ask the provider is made from the state read after `claimLock` (between the two, another refresher can have published a fresh slice or a backoff). A provider throttle (403/429) goes into the snapshot under that lock, and is ALWAYS tried on the scope's NOTE (`backoffNotePath`: lock-free, atomic, never deleted, an expired one is just not believed; when `ensureBackoffVisible` answers false, no reader finds this deadline in the note (the write failed, or what was written cannot be read back): a command keeps the deadline and tries again at a later chance (`persistIfNewer`), the refresher asks once in a cycle): the lock can be taken, the publish refused or its write failed (a publish that throws is one that did not happen), the snapshot unreadable, and a reader of another cache format rejects the snapshot whole, deadline included; it used to be dropped. A throttle counts as written only when the note holds it: after its attempt to publish, refused, failed or not, each writer (a command's `persistBackoff`, the refresher) asks `ensureBackoffVisible`, which writes the note unless the note already holds a deadline at least as late (`writeBackoffNote` reads the note back): one small write per throttle once it is held, never per cycle. Across a cache format bump the snapshot's deadline is read whatever the file's version (`backoffInEffect` with no state read), and a writer replacing a snapshot of another version notes that snapshot's believed deadline first (`writeState`). The backoff in effect is the later BELIEVED deadline of the snapshot's and the note's: every reader asks `backoffInEffect`, at the time it is then: the hot-path triggers (LAST, so the note is looked at only once a refresh would otherwise be started), the refresher when it decides, again before its second lane, and at publish, and a command arming its adapter. Every writer keeps the later believed one, comparing with `backoffInEffect` (the note included), never with the snapshot alone. `believedDeadline` is the one rule for a deadline: in the future and at most 30 minutes ahead; a value that is not believed neither beats nor hides a real one. A cycle whose base read is undefined (no snapshot of this scope and format could be read: none, unreadable, rejected) is paced by the scope's ATTEMPT RECORD (`attemptRecordPath`, beside the note, `{ at, count }`, never deleted, read only when no snapshot could be read), on every lane, the idle writers and the unknown-source publish included: under the lock and before anything else, a believed record that is not due returns (nothing written, nothing looked at), else the attempt is RECORDED (`admitAttempt`: `count + 1` written and read back) and the cycle goes on with no look; only an attempt that could not be recorded asks the look, last, and the gate fails closed only where the look SEES that a publish could not heal (`admitNoBaseCycle`): a publish is an atomic write whose temporary file is made in the cache directory and renamed over whatever is at the snapshot's path, and the replacement is ours, keeps the mode bits of whatever it replaces but a link and nothing else of the entry (no access-control entry of its own, no other owner), and gets what the directory gives a new file; the look answers from the entry's kind, its own bits and a probe, and names two states a publish cannot heal: a directory (the rename fails) and an entry that is not a link whose own mode denies its owner a read (the owner-read bit clear, whatever the kind: a regular file, refused or opened through its other bits or an access-control entry of its own; a pipe; a socket), unless a file made there with those bits still reads back: the directory's inherited permissions (`snapshotUnhealable`, through core's `lookAtEntry`: `lstat`, never following a link; where the owner-read bit of an entry that is neither a link nor a directory is clear, before any open, a probe file made beside the path with those bits, opened and removed, so the answer is measured, not predicted; an open only for a regular file). There a record that is not visible means the lock released, nothing published, nothing asked; in every other state (no entry; a symbolic link to anything, of which nothing is kept; and any other entry whose owner-read bit is set, whose replacement is ours and reads back: a pipe or a socket; a cache file refused, by an access-control list or another owner's 0600; a cache file that opened and was rejected: bad JSON, another format version, over the reader's bound, another scope's; and an entry whose bit is clear where the probe reads back) the cycle goes on whether or not the attempt could be recorded, and its publish heals in one cycle where the rename lands. An entry the system refuses to replace for a reason the look cannot see (an immutable or append-only flag: `lstat` reports no flag) is answered as it would be without the flag: where the look finds it healable (its owner-read bit set, or a file made there with its bits reads back) it is not gated: its cycle proceeds, its publish is one that did not happen, and the record left as its admission paces it where the record works; where it does not, it behaves as before this record existed. (`lookAtSmallFile` cannot ask it: it answers `unreadable` alike for a file it cannot open, one over its bound, and a link to nothing.) After the cycle, only while the lock is still held, a snapshot that reads back usable resets the record to `count: 0` (`settleAttempt`); the pace is one minute doubling to thirty (`attemptDelayMs`), with no age bound (the count is carried); the hot path asks it after the lock and before the note, on its no-snapshot branch alone. The limit as it is: where a publish could not heal the snapshot's path, a record nobody can read admits nothing (the provider is not asked, and the spawn per tick stays) until a publish could heal it (the entry removed, its owner-read bit set, or the directory's inherited permissions letting a new file with those bits be read) or the record works again, never because the snapshot file can be opened (a mode-000 file with its own allow-read entry opens, and its replacement would not); in every other state the cycle proceeds as it did before the record existed, and its publish ends the loop where the rename lands (not under an immutable or append-only flag, which the look cannot see: a file under one that this reader rejected is answered as it would be without the flag, paced with a working record and as before without one where the look finds it healable, gated where it does not; one that reads never reaches the record, so the provider is asked whenever a read is due and the snapshot is never replaced, as before). The lock API has one form: `holdsLock`, `releaseLock` and `publishState` take the token `claimLock` returned. A claim the claimer cannot read back is no claim (`claimLock` reads its token back; a lock nobody can read, in a cache directory whose new files nobody can read, admits no cycle: nothing asked, nothing published; the spawn per tick stays). Every file the CLI keeps (the snapshot, the note, the attempt record, the lock, the market cache, the run counter) is read through one descriptor, bounded and without waiting (`lookAtSmallFile`/`readSmallFile`, core's `files.ts`, re-exported by the CLI's `paths.ts`), and the user's config file through its no-follow form (`lookAtOwnFile`, under `readUserConfig`: `O_NOFOLLOW` at the open where the platform has it; on Windows, which has none, the entry is looked at, then opened, and the two must be one file, the same device and inode, else it is `symlink`), by the CLI and the MCP server alike; the only reads by path are the editors' settings file and standard input (the CLI), and none at all (the MCP server), pinned by each package's `cache-reads.test.ts`. A lock that vanished while a claimer looked at it is not removed (the claimer creates it once more); a stale one is taken over. Not closed, and stated in `claimLock`: two stealers of the same stale lock, and a lease lost while its owner still runs (the ownership check before a publish is not fencing). Not closed either, and stated in `writeBackoffNote`: the note's read-then-write is two steps, so two writers a few file operations apart can leave the earlier of two real deadlines.
